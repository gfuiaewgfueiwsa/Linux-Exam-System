# Linux 实训考核系统 v3.0.34

> **文档导航**：全部部署、配置、测试与调试命令见 [DEPLOY.md](./DEPLOY.md)；
> 轻量无虚拟机版本见 [考试系统简化版/README.md](./考试系统简化版/README.md)。
>
> 本仓库为公开仓库，**不含**成绩数据库、AI 助手记忆、QEMU/cloudflared 二进制与考试答案，
> 克隆后的准备步骤见 [DEPLOY.md §0](./DEPLOY.md#0-仓库内容说明必读)。

面向 Linux 基础命令课程的实操考核系统。学生端只有一个主界面，内含「练习」和「考试」两个模块；两个模块都接入**真实 Linux 虚拟机**（QEMU + Alpine），学生在浏览器终端里执行的每条命令都在真实内核中运行。

当前考题为 **41 道命令、满分 100 分**，严格顺序判题，判分依据虚拟机真实状态。**姓名即虚拟机绑定键**：同名学生始终回到自己原来那台 Linux。

## 更新公告 v3.0.34

- 虚拟机改为按**姓名**绑定：学生填姓名进入考试时，服务端先查有没有同名的未交卷会话，有就直接接管它的 sid 与虚拟机（池键为 `exam:<sid>`，同一 sid 即同一台机器、同一份持久磁盘），没有才新建。断网重连、刷新、关标签页、重启浏览器、甚至换一台电脑/换浏览器，只要填同一个姓名就回到原来那台 Linux，已创建的用户/目录/文件与已通过的题目全部保留。
- 姓名匹配折叠空白并忽略大小写：「张 三」「张三」「Zhang San」命中同一台机器；前后空格不影响。
- 查找与新建在同一把锁内完成：6 个同名请求并发到达只建 1 台虚拟机（实测 6 个请求返回同一个 sid，会话数 +1）。
- `POST /api/exam/resume` 改为**只找回、不新建**：先认浏览器里的 sid，sid 失效再认姓名；两者都找不到返回 404，由学生自己点「开始」重新进入。此前 sid 失效会静默新建一场考试，把原会话和虚拟机搁浅。
- 前端启动时凭 localStorage 里的姓名自动找回会话（sid 存在 sessionStorage，关标签页即丢，姓名不会丢）；姓名输入框下方明确提示绑定规则与「同名同姓会共用同一台机器」。
- 交卷后同名不再复用旧会话：`/api/exam/start` 会开一场新考试，`resume` 也只绑定新的未交卷会话，学生不会被困在已交卷的旧成绩里。
- 常驻终端按 `exam:<sid>` 复用，`attach()` 会关闭旧连接：同一会话开两个标签页时，新标签页接管终端、旧标签页断开，不会出现两个人同时敲同一台机器。
- 回归断言由 71 项增至 **83 项**（新增 T71–T81：同名复用、不重复分配、纯姓名找回、进度保留、失效 sid 兜底、空白归一、异名隔离、交卷后重开、并发同名）。

> 注意：纯姓名绑定意味着姓名就是凭证。同名同姓的两名学生会共用一台虚拟机与一份答卷，且知道他人姓名即可接管其会话。请确保考场内姓名唯一（必要时教师在姓名后加区分后缀）。

## 更新公告 v3.0.33

本轮为集中排错与性能优化，全部改动由 `tests\api_smoke.py`（71 项断言）与浏览器实测覆盖。

**安全与判分**

- 修复答案泄露：学生端 `/api/exam/state` 与考试启动响应此前把每题的 `expect`（标准命令）一并下发，学生打开 F12 → 网络即可看到全部 41 条答案；现在 `expect` 只对教师端 `/api/admin/live` 开放，学生端响应中 41 处 `expect` 降为 0 处。
- 修复教师端「手动判通过」在最后一题时不落成绩：`force_pass` 触发交卷后现在同步写入 `submissions` 并回收虚拟机，此前该生永远停留在「进行中」。
- 修复考题「重置为默认」后总分变成 105 分：默认题库分值与当前 100 分制对齐（19×3 + 21×2 + 1）。
- 修复学生乱序/误操作导致的命令镜像污染：终端桥接层此前把方向键、Home/End 等 ESC 转义序列当普通字符拼进命令行，按 ↑ 调历史会被判成 `[A`，Ctrl+L 清屏会污染当前命令；现在按 ESC 状态机跳过整段转义序列（练习与考试两条链路都已修复）。
- 教师端「学生成绩动态排行」现在把退出全屏扣分计入曲线，与姓名旁的实际得分一致。
- 移除已无人调用却能绕过顺序判题的 `POST /api/exam/select`：该接口允许学生直接跳到任意题号作答，与「只能由服务端判对后自动推进」的设计冲突；前端、教师端、测试均无调用方，连同 `ExamSession.select()` 一并删除（现在返回 404）。

**会话与断线恢复**

- 新增 `POST /api/exam/resume`：学生刷新页面/重开浏览器后凭 sessionStorage 中的 sid 直接回到原会话（姓名、已完成题目、剩余时间、终端历史全部保留），此前刷新即掉回主界面、原会话变成无人认领的僵尸。
- 修复未设开考时间时考试永不过期：看护线程此前只在 `deadline` 非空时才检查到时交卷，个人计时（默认 120 分钟）的会话到点不交卷、虚拟机永不回收；现在统一按 `remaining() <= 0` 判定。
- 练习令牌新增 6 小时 TTL 清扫：只回收从未连接过的僵尸令牌，正在使用的令牌不受影响。

**磁盘与内存**

- 修复考试预热镜像泄漏：`POOL.release()` 在虚拟机句柄已丢失（崩溃/重启恢复）时直接跳过磁盘清理，导致该生的 `pw-NN.qcow2` 与 `exam_slots.json` 映射永久残留、白占一个考试槽位；现在无论句柄是否存在都删除会话镜像与槽位映射。
- 新增无主预热镜像清扫：启动预置前与结束本场停预热后，删除 `data\lab\images\sessions\pw-*.qcow2` 中不在 `exam_slots.json` 里的镜像（必须在 QEMU 退出后执行），回收历史遗留的孤儿磁盘。
- 新增无主会话镜像检测（只报告、不删除）：启动时比对 `sessions` 表与磁盘上的 `<sid>.qcow2`，把找不到会话记录的镜像数量与体积打印到后台日志。这类镜像不能自动删——数据库损坏重建后「库里没有」会等于「全部在考学生的磁盘都没了」，因此只提示管理员确认后手动清理。
- 移除已废弃的命令历史备份机制残留代码：`history_path()` / `export_history()` / `import_history()` 全部删除。考试改用持久镜像后（v3.0.30），命令历史本就在虚拟机磁盘内，向 `Downloads\linux-exam-history\` 写备份已无意义；旧版本遗留的备份文件不再自动清理，可手动删除该目录。

**性能**

- 会话持久化体积从约 740 KB 降到约 5 KB：命令日志此前把每条命令的完整输出（可达数千字符）一起存进 SQLite，而教师端「机器命令日志」只读输入；现在只存命令本身（截断 500 字符）并保留最近 300 条。学生每敲一次回车都会整体写库，实测单次 `save_session` 6–9 ms（断言门槛 25 ms）。
- 学生端状态响应从约 94 KB 降到约 6 KB（去掉 `expect` 与冗余日志），教师端 8 名学生在线时轮询耗时 13–37 ms。

**前端**

- 主界面每 5 秒轮询闸门状态：开考前 5 分钟考试卡片自动解锁，无需学生手动刷新；未到提前窗口时卡片保持禁用并显示「未开始」。
- 姓名输入框支持回车直接进入考试。
- 修复终端监听器泄漏：`dispose()` 现在会移除 window resize 监听、清除 resize 防抖定时器并释放 `onData` 订阅，反复进出练习/考试不再累积回调。
- 修复刷新恢复后已完成题目不高亮：恢复会话时用后端返回的 `tasks[].done` 重建本地完成集合。
- 修复恢复全屏后遮罩不消失：重新进入全屏即隐藏 `#fs-lock`；并在进入考试 1.5 秒后确定性复查全屏状态（浏览器拒绝全屏时不一定 reject promise），未全屏则锁定界面。

**测试与文档**

- 新增 `tests\api_smoke.py`：71 项断言，在临时目录内起学生端 8010 / 教师端 8011，虚拟机池与金镜像预置全部替换为桩，不启动 QEMU、不触碰真实 `data\`。覆盖接口隔离、闸门、答案泄露、顺序判题、手动判通过、扣分、交卷与导出、到时自动交卷、考题管理、配置校验、刷新恢复、持久化体积与耗时、教师端轮询耗时、删除/清空、无虚拟机句柄时的磁盘回收、无主预热镜像清扫、无主会话镜像只读检测、命令镜像转义序列。
- 新增 `tests\ui_server.py`：浏览器实测用临时服务（`--before N` / `--open`），用于验证卡片禁用与自动解锁、进入考试、刷新恢复、交卷等页面流程。
- README 全面校正：题目数 87 → 41、满分 100、9 幕分组、只填姓名、严格顺序判题、无提示模块、持久镜像（不再是 `snapshot=on`）、`lab.json` 真实默认值、磁盘/内存实测占用、接口清单补全、自测命令改为现存脚本。

## 运行前置条件

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10/11 x64 |
| 权限 | 普通用户即可，**不需要管理员**、不需要 Docker / WSL / Hyper-V |
| 磁盘 | 基础约 1.1 GB（QEMU 运行库 740 MB + Alpine 云镜像 150 MB + 金镜像 200 MB）；每台考试虚拟机再占约 200 MB 独立镜像，默认预热 14 台 → 建议预留 5 GB |
| 内存 | 每台虚拟机 256 MB，练习池上限 16 台、考试并发上限 16 台（见 `lab.json`） |
| 网络 | 首次启动需下载 Alpine 云镜像（约 150 MB，可用国内网络） |
| 端口 | 8000（学生端）、8001（教师端）、22300–22900（虚拟机 SSH 转发，仅本机） |

QEMU 使用 TCG 软件模拟，**不要求 CPU 虚拟化**；代价是单台虚拟机启动约 40 秒，性能低于原生虚拟化。首次启动时若缺少金镜像，会自动开机预置（安装 bash/sudo/vim/less/procps/python3/openssh，约 2 分钟）。

### 环境目录

所有运行时文件都在项目内，不向工作目录外放置任何文件：

```
tools\qemu\bin\qemu-system-x86_64.exe        QEMU 9.2.3 主程序（含依赖 DLL）
tools\qemu\share\qemu\                        SeaBIOS / VGA / 网卡等固件
data\lab\images\alpine-cloud.qcow2           Alpine 3.24 云镜像（母本）
data\lab\images\golden.qcow2                 预置好的金镜像（学生机模板）
data\lab\images\sessions\                    每会话独立持久镜像（sid.qcow2 / pw-NN.qcow2）
data\lab\exam_slots.json                     考试会话 → 预热槽位映射（重启恢复用）
data\lab\id_lab / id_lab.pub                 SSH 密钥（虚拟机连接用）
data\lab\lab.json                            并发与内存配置
```

`lab.json` 当前默认值（文件不存在时按此生效）：

```json
{
  "max_vms": 16,
  "idle_seconds": 1800,
  "memory_mb": 256,
  "prewarm_vms": 2,
  "exam_prewarm": 14,
  "exam_capacity": 16,
  "boot_concurrency": 4,
  "image_concurrency": 2,
  "smp": 2
}
```

- `max_vms`：练习池同时运行的虚拟机上限。
- `idle_seconds`：历史保留字段，当前版本不再按空闲超时回收（练习断开即回收，考试虚拟机常驻至交卷）。
- `memory_mb`：单台虚拟机内存，最低 192 MB。
- `prewarm_vms`：练习池预热台数。
- `exam_prewarm`：开考前预热的考试虚拟机台数（编号 01–14）。
- `exam_capacity`：考试虚拟机并发上限，超出时学生在页面排队等待。
- `boot_concurrency` / `image_concurrency`：同时启动虚拟机 / 同时复制磁盘镜像的数量，用于压低启动瞬时 CPU 与磁盘峰值。
- `smp`：每台虚拟机 vCPU 数。

也可以用环境变量 `EXAM_LAB_DIR` 指定另一套环境目录（默认始终在项目内 `data\lab`）。

## 学生端

### 主界面

只有两个模块卡片，下方最多一行考试状态（未设置时间时不显示）。页面每 5 秒轮询闸门：开考前 5 分钟内考试卡片自动解锁并标注「可提前进入」，无需手动刷新。

### 练习

点「练习」→ 后台开一台新虚拟机（首次约 40 秒，页面右上角显示进度）→ 全屏真实终端，可执行任意命令：`useradd`、`passwd`、`chmod`、`vim`、`less`、`tar`、管道等全部真实生效。练习不计分、不影响成绩；点「返回」或关闭页面即断开并回收虚拟机。断线可点「重新连接」。

账号：`student` / `student`（可 `sudo -n` 直接提权），`root` / `root`。

### 考试

只填姓名即可进入（输入框支持回车提交）。**姓名就是虚拟机的绑定键**：服务端按姓名查未交卷会话，命中就接管原来那台 Linux，没命中才新建一台。左侧列出 41 道命令要求（按 9 幕分组），右侧是真实终端：

- **严格顺序判题**：题目列表不可点击选题，只有当前题对应的命令在虚拟机中真实生效后才自动推进到下一题；提前输入后续题目的命令不计分。
- 完成一项亮起一项，右上角实时显示得分（各题分值加权，满分 100 分）。
- 只显示「命令要求」（标题 + 任务描述），不下发标准命令；判题规则内置在服务端。
- 无提示功能、无提示扣分。
- 进入考试自动请求浏览器全屏；被强制退出全屏会弹出遮罩锁定界面，必须点「恢复全屏继续考试」，同时教师端记录一次退出全屏并扣 1 分（最低 0 分）。
- **断联只回自己的机器**：断网重连、刷新、关标签页、重启浏览器、换电脑换浏览器，填同一个姓名就回到原会话——已完成题目、剩余时间、虚拟机里创建的用户/目录/文件全部保留。姓名匹配折叠空白并忽略大小写。
- 同一会话开两个标签页时，新标签页接管终端、旧标签页自动断开，不会两人同敲一台机器。
- 交卷（手动交卷 / 到时自动交卷 / 教师结束本场）后出成绩单：分数、通过项数；交卷后同名再进入会开一场新考试。

判定依据是虚拟机真实状态（用户是否存在、密码是否设置、权限位、软链接目标、文件内容、进程当前用户与目录），不比对输入字符串。学生乱序作答卡住时，教师可在「进行中的学生 → 详情」里手动判定某题通过。

> **考场须知**：纯姓名绑定下姓名即凭证——同名同姓的两名学生会共用一台虚拟机与一份答卷，知道他人姓名即可接管其会话。请确保考场内姓名唯一，必要时在姓名后加区分后缀（如「张三-1班」「张三-2班」）。

## 常见问题

**第一次启动很慢？**
首次需要下载并预置金镜像（约 2 分钟）。之后每次新会话只是复制金镜像并启动，约 40 秒。开考前会按 `exam_prewarm` 预热考试虚拟机，学生进入时直接分配。

**提示「找不到 QEMU」？**
检查 `tools\qemu\bin\qemu-system-x86_64.exe` 是否存在；程序会自动搜索 `tools\qemu\` 与 `tools\qemu\bin\`。

**金镜像损坏或想重置学生机？**
关闭服务，删除 `data\lab\images\golden.qcow2`，重新启动即可自动重建。

**同时能考多少人？**
默认考试并发上限 16 台、开考前预热 14 台（`lab.json` 的 `exam_capacity` / `exam_prewarm`）。超出时后排学生会在页面等待，前面的学生交卷后自动进入。纯软件模拟下 CPU 占用随并发线性上升，教室机器性能不足时调小这两个值。

**学生能跑危险命令吗？**
可以执行 `rm -rf /`，但只影响他自己的虚拟机：每会话一份从金镜像复制的独立 qcow2，金镜像不受影响。该镜像在交卷/删除记录后删除；服务启动时还会清扫没有映射到任何在考会话的 `pw-*.qcow2` 孤儿镜像。

**磁盘涨得很快？**
每台考试虚拟机一份约 200 MB 的独立镜像。交卷、教师删除记录、一键清除都会回收；若曾直接关闭窗口导致残留，下次启动会自动清扫无主预热镜像（`pw-*.qcow2`）。另有少量 `<sid>.qcow2` 在数据库被清空后成为无主镜像，启动时会在后台日志报告数量与体积，确认没有学生在考后手动删除即可（系统不会自动删，避免数据库重建时误删在考学生的磁盘）。

**公网地址每次都变？**
Quick Tunnel 是临时隧道，重启即换新域名，新地址自动写入 `公网地址.txt`（一次生成 3 条，任选其一）。

**root 密码是多少？**
`root`；学生账号 `student` / `student`，并配置了免密 sudo（`sudo su` 不需要额外输入密码）。
